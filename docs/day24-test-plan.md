# Day 24｜核心流程测试清单

> 用途：集中找 Bug。逐项执行，**每一项都要留下「实际结果」**，不写「看起来正常」。
> 覆盖链路：打开检查台 → 读取数据 → 写入 → 刷新确认 → 修改 → 删除。
> 页面：`tools/checkup.html`（云端数据检查台）＋ 首页 `index.html`（添加卡片）。
> 数据表：`cards`（本项目对应教材的 plan_days/checkins 位）＋ `quiz_records`。

| 记号 | 含义 |

| ⚠️ | 行为异常但不算故障（如服务端按规则拒绝） |

## 执行结果（2026-10-10 实测）

驱动方式：用 CDP 连 headless Edge，**像用户一样点按钮 / 填输入框**，每步记录「预期 vs 实际 + 本步真实发出的请求 + 页面抛出的异常」。
脚本：`gcm/kq24/kq24_drive.js`（只读组）、`kq24_write.js`（写 / 改 / 删 / 连点组）；原始输出 `result_read_*.json`、`write_*.json`。

| 组 | 结果 | 备注 |
|---|---|---|
| A 打开与读取 | ✅ 全过 | 页脚 `d23-2026-10-09`；健康 200 ok:true；去向 0 条 localhost |
| B 写入 | ✅ 全过 | 201 → 409 → 换内容 201，闭环正确 |
| C 刷新持久化 | ❌ 失败 | **修完才通过**：接口 `id.asc` + 前端 `limit=5` → 新写的行永远进不了列表（Bug #2） |
| D 修改 | ⚠️ 部分 | D5 前端拦截 ✅、D6 只改难度 ✅；**D7 换 id 不重读 → 对照表张冠李戴（Bug #3）** |
| E 删除 | ✅ 全过 | 上膛不发请求、两步删除 200、再读 404、重复删 404、内置卡 403、上膛 10 秒自动复位 |
| F 刁钻输入 | ⚠️ 部分 | 空值 / 纯空格被前端拦（不发请求）；负数 id 400、非数字 id 被 `type=number` 拦；**F7 防呆检测整体不可用（Bug #1）** |
| G 重复与快速连点 | ⚠️ 部分 | G1 写入连点 5 次只发 1 次 POST ✅、G2 修改连点只发 1 次 PATCH ✅；**G3 删除连点发 2 次 DELETE（Bug #4）**，并发时第二次得 500（Bug #5） |

| # | 现象 | 优先级 | 本次处置 |
|---|---|---|---|
| 1 | ⑤ 面板「防呆检测」点了没反应，且控制台**没有红字** | 高 | **已修**（今日主任务） |
| 2 | ② 面板「库内总行数」显示 5（库里 26 行）；写完点重新读取看不到新行 | 高 | **已修**（余力加练） |
| 3 | 改了 id 但没重新读取就提交 → 「改前→改后」对照用的是上一条的值 | 中 | 记录，未修 |
| 4 | 删除按钮没有防抖，连点会发多次 DELETE | 低 | 记录，未修 |
| 5 | 并发双删 → 第二个请求 500（存在性校验与删除之间有竞态窗口） | 中 | 记录，未修 |
