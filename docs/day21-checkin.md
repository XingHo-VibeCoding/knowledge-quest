## 七、验收过程中一个「虚惊」记录（方法论的收获）

抽查接口时，我先用 `q=口语` / `q=周验收自检` 测关键词搜索，**两边都返回 `count=0`**，一度怀疑「中文搜索失效」。继续用 `q=英语`(3) / `q=提高效率`(1) / `q=验收`(1) 复测后确认：

- `口语` 是**科目名**（`subject` 字段），`周验收自检` 也只出现在 `subject`；
- 而契约写明 `q` 是「对 **front/back** 做包含匹配」，**不含 subject** → 返回 0 是**符合契约的正确行为**。

结论：**测出来的「异常」，先回头读契约再下判断。** 这次差一点把一个符合契约的行为当成 bug 报上去——验收里「对照基准」比「感觉不对」可靠。

## 九、每日一问

> **这周最花时间的是哪一步？你觉得值吗？**

**最花时间的是 Day 19 的「数据访问层重构 + 行为不变回归」那一段。** 不是因为拆代码本身难，而是因为「重构」最怕的不是写错，是**写对了但悄悄改坏了别的地方**。为了证明没改坏，我先用 `git archive` 导出重构前的代码副本，把 31 条固定用例在「重构前 / 重构后 / 公网」各跑一遍，做逐字节比对——这份「基线」的搭建比拆代码本身花的时间还多。

**值。** 因为它把「我觉得没坏」换成了「MD5 一模一样」。而且这份基线没浪费：今天是 Day 19 之后第 3 天，我又把它跑了一遍（本次四份快照分布完全相同、无 5xx），**上一次的投入变成了这一次 30 秒的结论**。更实际的是——如果没有它，今天验收第 ⑤ 项我就只能写「重构过，应该没问题」，那正是教材不允许的模糊表述。

第二花时间的是**接口地址收敛**（Day 20 把所有地址收进 `js/config.js`，并拆掉「接口失败就静默退回 mock」的兜底）。当时多花了些时间，但今天验收第 ⑧ 项「请求去向 0 条 localhost」能一次通过，靠的就是那时候把兜底拆干净了。
