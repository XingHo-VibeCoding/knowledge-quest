# Day 14｜轻量用户测试 — 测试清单与记录

> 任务来源：训练营 Day 14（第 2 周周验证日）。
> 原则：**用户测试不是问"好不好看"，而是观察别人能不能完成任务；测试者不应被提示下一步，否则测到的是你的讲解能力。**

## 一、给同伴的测试任务（发给同伴，全程不提示）

**复制即发的邀请话术：**

> 同学你好，我最近在做一个知识卡片网页，帮我 3 分钟试用一下：
> 打开这个链接 → 随便点一张卡片看看答案 → 找到其中一张卡片的"详情"页 → 搜一个你感兴趣的关键词 → 回到完整列表。
> 不用管好不好看，做完告诉我：哪一步你觉得别扭、找不到，或者点错了。谢谢！
> 链接：https://xingho-vibecoding.github.io/knowledge-quest/

**测试清单（观察者在旁边只记不说）：**

| # | 任务步骤 | 观察点 |
|---|---|---|
| 1 | 打开链接 | 首屏能不能看懂这是干嘛的？第一眼看向哪里？ |
| 2 | 点一张卡片看答案 | 会不会翻面？翻面后能不能翻回来？ |
| 3 | 打开一张卡片的"详情"页 | **能不能找到入口？点几次才点中？**（预演发现的疑似卡点就在这步） |
| 4 | 搜索一个关键词 | 知不知道在哪里输入？无结果时会不会清空恢复？ |
| 5 | 回到完整列表 | 用什么方式回来（面包屑 / 返回按钮 / 后退）？ |

记录要点：第一次点击点在哪、在哪里停顿、问了什么话。**只修一个最大阻塞点，修完让同伴复测这一步。**

## 三、预演走查记录（AI 无提示走查，非真人，先替同伴把路趟一遍）

- 方式：375×812 真机视口（Edge 设备仿真）打开**线上页面**，以"只按清单点"的方式走一遍，并脚本量化所有可点元素的点击目标尺寸。
- 量化结果（修复前）：57 个可点元素里 **33 个小于 44px 触屏最小点击目标**；其中最小、也最关键的是 **24 张卡片上的「详情 ›」入口：39×20px、12px 字**——它是进入详情页的唯一入口，旁边紧挨"点卡片翻面"，手指差几像素就会变成翻卡。同伴在第 3 步"打开详情"上最容易卡住。
- 其余小目标：导航/筛选块 31~34px 高（记录在案，今日不改，避免一口气全改）。
- 375px 无横向溢出；首屏文字能看懂用途（"把知识存成卡片，复习时就是一场游戏"）。

## 四、最小修复（只修一个最大阻塞点）

- **改了什么**：`css/style.css` 里「详情 ›」入口——从 39×20px 纯文字改为卡片底部 **309×44px 的通栏按钮**（44px = 触屏最小点击高度），"点卡片看答案"提示上移一行避免挤压。
- **修复后复测**：小于 44px 的可点元素 33 → **9 个**（剩余为导航/筛选块，属已知待办）；详情入口 309×44；375px 无横向溢出。
