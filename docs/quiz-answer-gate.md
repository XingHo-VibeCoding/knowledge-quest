# 闯关环节改造：先作答，再核对

> 2026-10-08 · 本地 `6d942da` / 远端 `1f0769c` · 改动 4 个文件 +220/−22

## 1. 为什么要改

原来闯关页的题面下方直接摆着「显示答案」按钮。手比脑子快 —— 一题还没自己想，答案已经翻开了，
"复习"退化成了"认读"：看过答案再点头，会觉得自己掌握了，其实只是认出来了。

改法就一条原则：**答案必须等自己先产出一遍才能看**。产出这一步不能省，也不许用"点一下按钮"代替。

## 2. 改了什么

### 2.1 三阶段流水线

| 阶段 | `Quiz.stage` | 页面上有什么 | 页面上**没有**什么 |
|---|---|---|---|
| ① 作答 | `ask` | 题面 + 输入框 + 「提交答案」（空输入时按钮灰掉） | 答案、判定按钮 |
| ② 核对 | `judge` | 正确答案 + 我写的答案 + 系统预判 + 「✓ 答对了 / ✗ 没答上」 | 输入框（已收起）、提交按钮 |
| ③ 判定 | — | 下一关（回到 ① 的干净状态）或成绩单 | — |

降级出口：**「想不出来？直接看答案」**。走这条路也进阶段 ②，只是"我写的答案"记为
`（空 · 直接看了答案）`——复盘时能分清"不会"和"写错"，不把两者混成一个"错"。

### 2.2 「答案不出现」是怎么保证的

不是靠 CSS 遮住，是靠**不写进去**。`Quiz.renderQuestion()` 每次出题做四件事：

```js
e.back.textContent = '';              // 清空上一题的答案文本
e.backWrap.classList.add('hidden');   // 答案容器收起
e.answerBtns.classList.add('hidden'); // 判定按钮收起
e.answerInput.value = '';             // 输入框清空
```

只有 `Quiz.submit()` 里才会把 `card.back` 写进 DOM。所以未提交时，
答案**既不可见、也不在 DOM 文本里**（实测断言过 `#qBack` 文本为空）。

### 2.3 比对规则（是预判，不是裁判）

```js
compare(mine, answer) → true / false
```

| 步骤 | 做法 |
|---|---|
| 归一化 | 转小写 → 去所有空白 → 去中英标点（`，。、；：！？""''（）【】《》,.;:!?"'()[]{}<>=~～-_—·…「」『』`） |
| 拆候选 | 答案按 `/`、`、`、`;`、`；`、`\|` 拆成多个可接受写法，任一命中即算对 |
| 判对条件 | ① 完全相同；② 一方包含另一方且短串 ≥ 4 字符；③ LCS 相似度 ≥ `PASS`（0.75） |

**为什么不自动判死**：同一个意思可以有十种说法，机器判不了。所以预判只做两件事 ——
给用户一个起点、把可能判错的那一个按钮用紫框标出来（`.suggested`）。
**改判权始终在用户手里**：换个说法答对了，点一下「答对了」就改回来。

### 2.4 一次答题的数据流（正向）

```
① 出题    Router → showView('quiz') → Quiz.start(cards) → renderQuestion()
                                                    └─ 答案不进 DOM（backWrap hidden）

② 输入    用户敲字 → input 事件 → syncSubmit() → 空则 disabled、非空则 enabled
                                                   └─ Enter → onKey() → submit()（输入法组字时不拦）

③ 提交    submit() → 写入 card.back → compare() 算预判 → 展开答案区 + 判定按钮
                                          └─ 命中哪个按钮，哪个按钮加 .suggested 紫框

④ 判定    judge(true/false) → results.push({card, correct, mine}) → idx++
                                                    ├─ 还有题 → renderQuestion()（回到 ①）
                                                    └─ 打完了 → finish() → KQStore.saveBest()
```

### 2.5 数据「不会去」的地方（反向声明）

| 数据 | 不会去哪 | 为什么 |
|---|---|---|
| 我写的答案（`mine`） | **不发请求、不上传** | 目前纯前端自测，成绩只存 `localStorage`。想接后端记录是另一天的事 |
| 答案文本（`card.back`） | **不在作答阶段进 DOM** | 这是本次改造的核心不变量，被断言守着 |
| 成绩（`score`） | **不改 `cards` / `quiz_records` 表** | 成绩单只写本机 `KQStore.saveBest()`，云端写入是检查台那条独立链路 |
